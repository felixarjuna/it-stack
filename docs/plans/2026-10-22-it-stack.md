# it-stack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `felixarjuna/it-stack`, a public Claude Code plugin of ten `<verb>-it` skills, adopt it in PERKIWeb, and prove it with one real `run-it` pass.

**Architecture:** Each skill is a short `skills/<name>/SKILL.md`. Skills read project facts from a `## it-stack` section in the project's CLAUDE.md, reference other plugins' skills instead of copying them, and use T3 Code tools only in `run-it` (and for PR linking when present). A zero-dependency Node validator, run by `node --test` locally and in CI, keeps the skill files, manifests and README consistent and keeps project-specific or private text out of the public repo.

**Tech Stack:** Markdown skills (Claude Code SKILL.md format), Claude Code plugin + marketplace manifests, Node 26 (`node:test`, no npm dependencies), GitHub Actions, `gh`.

**Spec:** `docs/specs/2026-10-22-it-stack-design.md`

## Global Constraints

- Repo: `felixarjuna/it-stack`, public, MIT, at `C:\Users\Admin\Desktop\programming\projects\@oss\it-stack`.
- Install commands: `/plugin marketplace add felixarjuna/it-stack`, `/plugin install it-stack@it-stack`.
- Skill names match `^[a-z]+-it$`; the ten are `do-it`, `plan-it`, `sort-it`, `split-it`, `fix-it`, `build-it`, `run-it`, `prove-it`, `ship-it`, `merge-it`. Entry points Felix types: `do-it`, `fix-it`, `build-it`, `run-it`.
- PR body sections in order: Why, What changed, Scope, Verification, `Closes #n`, Screenshots (phone 390px + desktop), attribution line. Chat gets only the PR link. Never merge without Felix saying "merge".
- At most 3 open PRs in the repo; at most one open PR adding a migration. Counts every open PR, whoever opened it.
- Questions to Felix come in one batch. Already-done issues close only after Felix replied to the batch.
- Security-related issues are never worked by `run-it` and never mentioned in public issues, PRs or commits.
- Nothing project-specific in the stack: no PERKIWeb names, commands or data. Project facts come from the project's `## it-stack` section.
- `run-it` requires T3 Code; every other skill works in any Claude Code client.
- Other stacks are referenced, not copied: Matt Pocock's user-only skills are read from `~/.claude/plugins/cache/*/mattpocock-skills/*/skills/*/<name>/SKILL.md` (newest version); model-invocable ones (superpowers `brainstorming`, `systematic-debugging`, `test-driven-development`, mattpocock `grilling`) through the Skill tool; each with a short inline fallback.
- Confirmed T3 Code behaviour (2026-10-22): a thread can hold many linked PRs; one PR can be linked to two threads; a watch belongs to the watching thread, so a session thread settling doesn't end the control room's watch.

## Review Focus

1. **Project without an `## it-stack` section** → skills detect `check` from package.json scripts and state the assumption in Verification instead of failing. Pinned in Task 2's ship-it text and in validator test `project facts example parses`.
2. **A PR already open for the issue/branch** (re-run of `ship-it` or `build-it`) → update the existing PR body instead of opening a second PR. Pinned in Task 2's ship-it step and Task 6's run-it resume rules.
3. **Control room restarted** (thread lost or settled) → `run-it` rebuilds from `.it-stack/run.md` plus `gh pr list`, re-links and re-watches open PRs, never relaunches an issue that already has a session or PR. Pinned in Task 6.
4. **Referenced plugin missing** (no mattpocock-skills/superpowers installed) → the inline fallback runs and the skill names the plugin to install once. Pinned by validator test `skills that reference another plugin carry a fallback`.
5. **Private text leaking into the public repo** → validator rejects known private markers. Pinned by validator test `rejects project-specific or private text`.
