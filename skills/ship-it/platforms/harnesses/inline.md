# Inline execution

Use the current coding session. No external harness, daemon, model catalog or worker launch is required. Record a local run-owner ID and absolute workspace/plan path; retain it across resume. Unknown previous ownership requires takeover before scheduling.

Execute one implementation at a time. Use the selected Git host adapter for remote operations. Reconcile on owner activity and after local shipping/merging. If automatic watches are unavailable, say that external changes will be noticed on the next activity. Never claim an idle conversation is polling.

Questions stay in the current conversation. Keep separate records for any pre-existing external workers; switching to inline does not cancel or replace them. Cleanup only after releasing the workspace, confirming it is clean and switching to a safe checkout; never remove the current workspace.
