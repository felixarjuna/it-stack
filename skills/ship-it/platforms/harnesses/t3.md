# T3 Code harness

Implements [harness operations](../contracts.md), independently of Git host. Inspect live tool schemas; tool availability depends on the T3 integration/version. GitLab operations use the GitLab adapter, never a T3 GitHub-only PR tool.

| Operation | Mapping |
| --- | --- |
| `identify/list` | `t3_thread_list`, including `currentThreadId` and relevant active/settled threads |
| `capabilities` | live tool catalog plus `orchestrator_capabilities` provider/model catalog and inherited options |
| `read` | `t3_thread_read`; bounded `t3_thread_wait` when available |
| `send` | `t3_thread_send` with target `threadId`, `mode: "queue"` and exact message |
| `release` | verify stopped/released thread and clean workspace, then use supported platform cleanup; if unavailable retain it |

Resolve explicit task model/provider/options, then project preferences, then current inherited selection. Preserve the existing Claude Code default `claude-opus-5-5` on `claudeAgent` only for a legacy Claude default request and only if available. Never require a Claude provider for another coding agent. Validate every resolved choice against `orchestrator_capabilities`; inherited options apply only to the same provider/model, unless individually compatible. Review agents use the same resolution rules, but require their own authorization.

Launch after persisting a reservation:

```text
t3_thread_launch {
  title: "<run-id> <issue-url> <title>",
  modelSelection: { instanceId: "<resolved>", model: "<resolved>", options: <supported> },
  workspaceStrategy: { type: "worktree", baseRef: "<default branch>", branch: "<unique branch>", startFromOrigin: true },
  message: "Use build-it. Issue: <url>. Control room: <id>. Central run state: <absolute path>. Resolved platform context: <context>. Report questions, review URL and unrelated failures here using the harness adapter."
}
```

Check the returned selection and retain full thread/workspace IDs and actual path. After error/lost response, list and inspect threads matching run/issue/branch before retrying. No assumed idempotency key. If the selected remote is not origin and the installed workspace API cannot target it, prepare an explicit safe workspace through supported tools or report the limitation; never branch from the wrong project.

Optional GitHub bridge: when supported, `link_pull_request` and `watch_pull_request` for worker/control-room IDs; `unwatch_pull_request` when done. On wake-up, if a control room is settled, use `t3_thread_organize` to unsettle and restore supported watches. For GitLab or a missing bridge, use activity-driven reconciliation and plain MR URLs. A missing bridge does not invalidate T3 session support.
